# Rivertide website — agent entry point

Build cash-flow decision software for seasonal small-business owners. Optimize understanding, not decorative complexity.

## Read selectively
- Always start with [current status](docs/STATUS.md) and git status.
- Product scope/copy: [PRODUCT](docs/PRODUCT.md).
- UI/branding: [DESIGN](docs/DESIGN.md), [palette](brand/PALETTE.md), [approved logo](brand/APPROVED-LOGO.md).
- Forecast/input behavior: [ACCEPTANCE](docs/ACCEPTANCE.md).
- Commands/tools/release process: [WORKFLOW](docs/WORKFLOW.md).
- New work: copy [TASK-TEMPLATE](docs/TASK-TEMPLATE.md) into the task brief, not into every conversation.

## Hard boundaries
Preserve forecast math and verified sample values unless explicitly scoped. No invented claims, guarantees, cloud sync or founder history. Use approved monochrome, Public Sans and Signature R artwork. Shared design CSS must match across repos.

Keep changes reviewable; preserve user work. Test relevant behavior and report evidence. No production merge/deployment without authorization. Do not treat old notes or a successful preview as current production state.

App repo owns shared product/design/acceptance contracts; marketing mirrors them. Current explicit user direction takes precedence over older documentation. Do not load the whole archive by default.
